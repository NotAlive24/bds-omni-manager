First-time setup

Upstream instructions
  1. Install the BedrockNodeTunnel Arch package using the upstream release's PKGBUILD.
  2. Run nethernet-client once and complete the claim link or code printed in its output. The upstream client stores the token itself.
  3. Use Start tunnel above. Use Enable at login separately if you want systemd to start the tunnel with your user session.
  4. Copy the exact four BDS networking settings from your Bedrock Node dashboard, paste them into the import box, review, apply, and restart BDS.
  5. Give players the public IP and port shown in your Bedrock Node dashboard. That public port can differ from the local BDS server-port.
Optional: loginctl enable-linger "$USER" keeps your systemd user services available across logout and before login. This does not make the manager-owned BDS process a boot service.

Process-control model

The manager owns the BDS process it launches, so it can reliably send console commands through standard input and read output. Closing the browser leaves the manager running; pressing Ctrl+C in its terminal gracefully stops the managed BDS process. BDS processes started by other scripts, terminals, or systemd cannot be attached to safely by this standard-library build.

If your current server is launched by an existing mcserver, WaterdogPE, tmux, or systemd setup, stop that instance before starting BDS here. The Networking panel manages the upstream BedrockNodeTunnel systemd user service. Other proxy or tunnel services such as Playit, WaterdogPE, or Endstone remain separate.
